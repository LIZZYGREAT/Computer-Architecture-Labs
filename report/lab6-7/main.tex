\reportsection{三、Lab6：算术逻辑指令的扩展}
\textbf{1. 译码、立即数和可变移位。}

在 ID 阶段加入 \code{add/addi/sub/slti/sltiu/andi/ori/xori/sllv/srlv/srav} 等指令。除了选择 ALU 的运算类型，还要判断指令是否真正读取 \code{rs}、\code{rt}，以便原来的相关检测能够识别新指令。

立即数有两种常见的扩展方式：\code{addi/slti/sltiu} 按指令规定进行符号扩展，而 \code{andi/ori/xori} 使用零扩展。例如立即数 \code{0x8000} 扩展后可以是 \code{0xFFFF8000} 或 \code{0x00008000}，选择错了就会影响 ALU 结果。EX 阶段通过下面的控制选出正确操作数，代码节选自 \code{EXE_stage.v}：

\begin{lstlisting}
assign es_imm_zero_extend = es_src2_is_imm &&
    (es_alu_op[4] || es_alu_op[6] || es_alu_op[7]);
assign es_alu_src2 = es_src2_is_imm ?
    (es_imm_zero_extend ? {16'b0, es_imm} :
                          {{16{es_imm[15]}}, es_imm}) :
    es_src2_is_8 ? 32'd8 : es_rt_value;
\end{lstlisting}

\reportfig{01_alu_immediate.png}{0.98}{立即数指令在 EX 阶段的输入、运算结果和后续 WB 写回波形}

立即数波形中，\code{es_pc} 依次经过 \code{BFC0002C}、\code{BFC00030} 和 \code{BFC00034}。其中 \code{andi} 和 \code{ori} 相关指令把 \code{0x8000} 作为零扩展后的操作数，ALU 输出 \code{0x00008000}；\code{xori} 使用 \code{0xFFFF} 时，结果为 \code{0xFFFF0000}。截图中可以同时看到 \code{es_alu_src2}、\code{es_alu_result} 和稍后出现的 WB 数据，说明立即数处理和写回方向符合测试要求。由于是流水线，WB 的 PC 比当前 EX 的 PC 落后几个时钟周期，这也是波形中两组 PC 不完全同步的原因。

可变移位和固定移位的区别是：移位位数来自寄存器 \code{rs} 的低 5 位，被移位数据来自 \code{rt}。逻辑右移在左侧补零，算术右移会保留原数据的符号位。实际 ALU 直接使用 \code{alu_src1[4:0]} 控制移位。

\reportfig{02_variable_shift.png}{0.98}{SLLV、SRLV、SRAV 的移位量、输入数据和 ALU 输出波形}

移位截图中，\code{es_pc=BFC00044/48/4C} 对应连续三种可变移位，低 5 位移位量均为 5，ALU 输出依次为 \code{FFF00000}、\code{04000000} 和 \code{FC000000}。其中最后一个结果的高位仍为 1，符合算术右移的符号扩展规则。另一个移位量为 31 的定向测试也通过，对应结果为 \code{80000000}、\code{00000001} 和 \code{FFFFFFFF}。这些结果说明移位量选择以及逻辑/算术移位的处理正确。

\textbf{2. 与原有前递和停顿机制的衔接。}

增加指令后，不能只看单条指令的计算值。例如第一条指令刚算出某个寄存器结果，下一条指令马上读取它，如果还从寄存器堆取值就可能拿到旧数据。原有前递按 EX、MEM、WB 的顺序选取最近的有效生产者；如果最近生产者是尚未从 RAM 得到值的 load，就先让 ID 等待。

\begin{lstlisting}[language={}]
对 ID 指令需要读取的每个源寄存器：
    先检查 EX / MEM / WB 中是否存在更早的写入者
    if 最近写入者的结果已经有效:
        用前递结果作为操作数
    else if 最近写入者的结果还没有准备好:
        保持 ID 指令，等待后续周期
    else:
        直接读取寄存器堆
\end{lstlisting}

\wavepair{03_forwarding_load_use-BFC00054.png}{普通运算之间的数据前递}{03_forwarding_load_use-BFC00084.png}{load-use 等待}{相关检测、前递选择和 load-use 停顿波形}

上半图中，\code{BFC00054} 附近的运算可以看到 \code{ds_forward_rs_ex}、\code{ds_forward_rt_ex} 等选择信号，后续写回 \code{r21=00002468}，说明相邻指令使用了前级产生的新值。下半图中，\code{lw} 后的一条指令在 ID 等待，\code{ds_pc=BFC0008C} 保持了一个额外周期，\code{ds_stall} 对应拉高；随后暂停解除，最终得到 \code{r31=00008000}。这个过程说明前递可以减少一般 ALU 相关造成的等待，而 load 的结果尚未到达时仍会正确停顿。

\reportsection{四、Lab6：乘除法 IP 与 HI/LO}
\textbf{1. 运算结果的保存方式。}

MIPS 乘除法使用两个特殊寄存器 HI 和 LO。乘法计算 64 位结果，把高 32 位放在 HI，低 32 位放在 LO；除法把余数放在 HI、商放在 LO。\code{mfhi/mflo} 再把这些值读到通用寄存器，\code{mthi/mtlo} 则可以直接修改对应特殊寄存器。

我新增了 \code{hilo_unit.v} 连接乘法和除法 IP。乘法器使用 33 位操作数的符号扩展方式，兼顾有符号和无符号 32 位乘法；有符号除法先将负数变成幅值送给无符号除法器，等商、余数返回后再恢复符号。HI/LO 的最终写入在单元内部管理。

\wavepair{04_mult_signed.png}{有符号 MULT}{04_multu_unsigned.png}{无符号 MULTU}{乘法 IP 结果与 HI/LO 寄存器波形}

有符号乘法图中，输入分别为 \code{45B90738}、\code{D70D64F0}，波形中乘积高低 32 位为 \code{F4D903BB:0A20A480}，并写入 HI/LO。无符号乘法图中，操作数 \code{99C9A500} 和 \code{6C1A1B60} 得到 \code{40F0C088:B204E000}。在这两个测试片段中，都能观察到乘法请求及 HI/LO 值更新，后续读出也与参考结果一致。

\textbf{2. 多周期等待与流水线握手。}

乘除法 IP 可能要等待多个时钟周期，EX 不能在请求刚发出后就将该指令丢掉。我让 EX 在结果未完成时保持当前指令，等 \code{done} 之后才允许进入后一级。对应控制代码如下：

\begin{lstlisting}
assign es_hilo_start = es_valid && es_hilo_multdiv &&
                       !es_hilo_busy && !es_hilo_done;
assign es_hilo_consume = es_valid && es_hilo_done && ms_allowin;
assign es_ready_go = !es_hilo_multdiv || es_hilo_done;
assign es_allowin = !es_valid || (es_ready_go && ms_allowin);
assign es_to_ms_valid = es_valid && es_ready_go;
\end{lstlisting}

这里 \code{es_ready_go} 表示当前 EX 指令是否已经准备好向 MEM 推进。对于乘除法，结果未完成时它为 0，IF 和 ID 也通过原来的 \code{allowin} 传递关系停止推进。等结果完成后，再发出一次 \code{consume}，避免重复提交同一个结果。除法的被除数和除数分别使用有效、就绪握手，两路数据会保持到被同时接收。

\begin{lstlisting}[language={}]
EX 接收到一条 MULT / DIV 指令
    锁存源操作数，向对应 IP 发出一次请求
    while IP 尚未返回完成结果:
        EX 保留当前指令，IF/ID 不继续推进
    将乘积或商、余数写入 HI/LO
    等后一级允许接收时，消费完成结果一次
    继续执行下一条指令
\end{lstlisting}

\wavepair{05_div_stall_branch-BFC00008.png}{DIV 开始、EX 保持}{05_div_stall_branch-BFC0000C.png}{DIV 完成与后继分支推进}{除法期间 EX 停顿及完成恢复波形}

这组短程序先使 \code{r1=-23}、\code{r2=5}，随后执行 DIV。第一张波形中，\code{es_pc=BFC00008} 保持在除法指令上，\code{es_hilo_busy} 变为 1，\code{es_ready_go} 与 \code{es_allowin} 为 0；ID 中的分支指令也保持等待。第二张波形中，除法单元进入完成状态，HI、LO 分别变为 \code{FFFFFFFD} 和 \code{FFFFFFFC}，对应余数 $-3$、商 $-4$。随后 \code{es_ready_go} 恢复，流水线继续推进，说明除法运算和后续指令之间的顺序没有被打乱。

单独的 HI/LO 单元测试还检查了多次乘除请求、完成保持和复位取消，测试结果 PASS：总共接受 3 次乘法和 4 次除法，完成并提交 6 次，另有一次除法在复位时取消。

\reportsection{五、Lab7：转移指令与延迟槽}
本次新增 \code{j/jalr/bgez/bgtz/blez/bltz/bgezal/bltzal}。转移指令主要在 ID 阶段处理：先根据 \code{rs} 的值判断分支条件，再计算目标 PC。\code{jalr} 从寄存器中读取跳转目标，还需要把当前指令的返回地址写入指定寄存器。

原有 CPU 保留 MIPS 延迟槽，即分支或跳转指令后面的紧邻一条指令会执行一次，之后才到跳转目标。因此，对于带链接的跳转，保存的返回地址为 \code{PC+8}。如果 EX 正因除法等待，ID 中的转移指令就不能连续多个周期重复发出重定向。RTL 中的关键门控如下：

\begin{lstlisting}
assign br_taken = (inst_j || inst_jal || inst_jr ||
                   inst_jalr || ds_branch_cond_taken) &&
                  ds_valid && ds_ready_go && ds_allowin;
\end{lstlisting}

\wavepair{06_branch_delay_slot_jalr-BFC70398.png}{JALR 的链接与延迟槽}{06_branch_delay_slot_jalr-BFC96694.png}{BGEZ 后的延迟槽 MFHI}{Lab7 转移指令、PC 和写回路径波形}

上图的 \code{JALR} 位于 \code{PC=BFC70398}，链接结果写入 \code{r31=BFC703A0}，正好是 \code{PC+8}。它后面的延迟槽指令位于 \code{BFC7039C}，其 \code{LUI} 写回 \code{r8=800D0000}。下图对应一条 \code{BGEZ}，可以看到分支路径继续执行，延迟槽中的 \code{MFHI} 写回 \code{r15=00004000}。这些写回顺序与对应课程功能测试一致。

前面除法短程序也包含一条立即跟在 DIV 后面的 taken \code{BEQ}。DIV 完成后，延迟槽把 \code{r3} 写成 \code{00000055}；fall-through 的 \code{BFC00014} 没有产生写回；之后目标路径读出商 \code{FFFFFFFC} 和余数 \code{FFFFFFFD}，并写入标记 \code{r7=00000066}。这个例子把多周期 EX 等待、分支推进和延迟槽执行联系到了一起。

\reportsection{六、Lab7：字节、半字及非对齐访存}
\textbf{1. 以 32 位 RAM 实现不同宽度访问。}

已有 CPU 的 \code{lw/sw} 每次读取或写入一个 32 位字。加入 \code{lb/lbu/lh/lhu}、\code{sb/sh} 和 \code{lwl/lwr/swl/swr} 后，需要根据地址最低两位判断访问哪个字节或半字。本工程采用小端方式，偏移 0 对应读出字的最低 8 位，偏移 1 对应第二个字节，以此类推。

在 ID 阶段通过 \code{mem_op} 区分各访存指令，EX 计算有效地址并准备写掩码，MEM 根据返回的整字数据完成字节提取、符号扩展或合并。例如 \code{lb} 的一部分代码如下：

\begin{lstlisting}
if (ms_mem_op[`MEM_OP_LB]) begin
    case (ms_alu_result[1:0])
        2'd0: mem_result = {{24{data_sram_rdata[7]}},
                            data_sram_rdata[7:0]};
        2'd1: mem_result = {{24{data_sram_rdata[15]}},
                            data_sram_rdata[15:8]};
        // 其余偏移选择更高的字节通道
    endcase
end
\end{lstlisting}

\wavepair{08_byte_half_load-BFC5D874.png}{LB 符号扩展}{08_byte_half_load-BFC1D2B4.png}{LBU 零扩展}{字节加载的 RAM 返回数据、MEM 处理结果和 WB 写回波形}

两张波形分别对应 \code{LB} 与 \code{LBU}。在 MEM 级可以看到 RAM 返回的整字数据以及 \code{mem_result}；\code{LB} 的结果为 \code{FFFFFFAF}，说明最高位为 1 的字节被扩展成负数；\code{LBU} 的结果为 \code{000000FF}，高 24 位补零。结果随后经过写回级，与测试要求相符。

\wavepair{08_byte_half_load-BFC6ABC0.png}{LH 符号扩展}{08_byte_half_load-BFC7E7D4.png}{LHU 零扩展}{半字加载的选择、扩展及写回波形}

半字加载也有相同区别。\code{LH} 的输出为 \code{FFFFBE4D}，而 \code{LHU} 的输出为 \code{0000C5E0}。波形显示 MEM 阶段依据地址选择对应 16 位数据后，再交给 WB 写回，反映出有符号和无符号加载分别进行了正确的高位扩展。

\textbf{2. 字节写使能和写入数据。}

写入时不能覆盖同一个 32 位字中无关的字节，因此 \code{data_sram_wen[3:0]} 用来指定哪些 byte lane 可以更新。例如 \code{sb} 会把写入数据移动到目标字节位置，并且只打开一个写使能位：

\begin{lstlisting}
else if (es_mem_op[`MEM_OP_SB]) begin
    es_store_wen_r  = 4'b0001 << es_alu_result[1:0];
    es_store_data_r = es_rt_value <<
                      {es_alu_result[1:0], 3'b000};
end
\end{lstlisting}

\wavepair{07_partial_store_mask-BFC8E15C.png}{SB 单字节写入}{07_partial_store_mask-BFC1AACC.png}{SH 半字写入}{部分写入指令的字节写使能和 RAM 写数据波形}

在 \code{SB} 波形中，\code{data_sram_wen=0001}，写数据为 \code{7955C40A}，表示只有最低字节通道有效；\code{SH} 对应 \code{wen=1100}、\code{wdata=36000000}，说明本次写入选择高两个字节通道。波形中的 \code{data_sram_addr}、\code{data_sram_wen} 和 \code{data_sram_wdata} 与 EX 产生的写入控制对应，反映了写掩码被正确送到 RAM 接口。

\wavepair{07_partial_store_mask-BFC8759C.png}{SWL 按偏移选择低侧字节}{07_partial_store_mask-BFC2B5CC.png}{SWR 按偏移选择高侧字节}{非对齐存储指令的写掩码和数据移位波形}

\code{SWL/SWR} 需要按照地址偏移只修改整字的一部分。截图中的 \code{SWL} 给出 \code{wen=0011}、\code{wdata=00008EA8}，\code{SWR} 给出 \code{wen=1110}、\code{wdata=13424C00}。两种指令启用的字节通道不同，说明 EX 阶段根据指令类型和地址偏移选择了相应的部分写入规则。

\textbf{3. 非对齐加载中的新旧数据合并。}

\code{LWL/LWR} 与普通 \code{LW} 的区别是：读取出来的数据会与目标寄存器 \code{rt} 原来的部分内容合并。这样一条指令既读取 \code{rt}，又向它写回结果，所以必须把旧 \code{rt} 纳入原有 RAW 检测和前递。MEM 级根据地址偏移执行拼接，例如：

\begin{lstlisting}
// LWL: address offset = 1
2'd1: mem_result = {data_sram_rdata[15:0],
                    ms_rt_value[15:0]};
\end{lstlisting}

\wavepair{09_unaligned_load_merge-BFC5BEAC.png}{LWL 与旧 rt 合并}{09_unaligned_load_merge-BFC9A1E0.png}{LWR 与旧 rt 合并}{非对齐加载时 RAM 数据、旧寄存器值和合并结果波形}

\code{LWL} 的波形中，旧 \code{rt=F507F480}、RAM 返回 \code{79E8D3EE}，得到合并结果 \code{E8D3EE80}；\code{LWR} 中旧 \code{rt=ED6D7900}、RAM 返回 \code{CE7208CC}，合并结果为 \code{ED6DCE72}。两张图都能看到 \code{ms_rt_value}、\code{data_sram_rdata} 和 \code{mem_result} 的对应变化，说明 MEM 级在保留旧数据片段的同时补入了正确的内存字节。

\textbf{4. 写入后的读回检查。}

对于 store，仅检查 \code{wen} 和 \code{wdata} 还不够直观，所以课程测试也安排了后续读取同一内存位置。结合读回波形，可以观察到部分写入后的整字内容。

\wavepair{10_store_readback-BFC8E170.png}{SB 后读回}{10_store_readback-BFC1AAE0.png}{SH 后读回}{字节和半字写入之后的 LW 读回波形}

对应的整字读回结果分别为：\code{SB} 后 \code{B4F0090A}、\code{SH} 后 \code{36008848}。例如第二个结果中，高半字变为 \code{3600}，低半字保持 \code{8848}，符合高半字写入的预期。

\wavepair{10_store_readback-BFC875B0.png}{SWL 后读回}{10_store_readback-BFC2B5E0.png}{SWR 后读回}{非对齐部分写入之后的 LW 读回波形}

\code{SWL} 写入后读回 \code{CEEB8EA8}，\code{SWR} 写入后读回 \code{13424CE8}。把这些读回值与前面的写掩码一起观察，可以看到 RAM 只修改了指定的字节范围，未选中的字节仍被保留。

另外还有一组较短的连续依赖测试：把 \code{lw} 后的数据立即用于 \code{sb/sh/swl/swr}，再通过加载检查结果，并测试连续 \code{lwl/lwr} 和 \code{lw} 后的条件分支。测试对 9 次 store 的地址、写使能和写数据进行了检查，25 条写回记录也全部与参考 CPU 匹配，结果为 PASS。

\reportsection{八、实验总结}
这次实验在已经实现前递和流水线阻塞的 CPU 上，继续补充了运算、转移和访存指令。算术逻辑部分主要是增加译码、立即数扩展和可变移位；乘除法部分增加了 IP 及 HI/LO 管理，还需要让 EX 在等待期间保持指令；转移指令要注意分支条件、返回地址和延迟槽；访存指令则要处理不同的数据宽度、字节写使能，以及非对齐访问时的新旧数据合并。

结合这次的波形，比较容易理解为什么指令扩展不能只增加一条 ALU 操作。例如除法期间，EX 的 \code{ready_go} 为 0，后面的分支就保持等待；当结果准备好以后，HI/LO 更新，流水线再继续前进。访存也是类似的道理：\code{SB/SH/SWL/SWR} 会选出不同的写使能，而 \code{LWL/LWR} 还要把旧 \code{rt} 保留到 MEM 才能合并出正确结果。

最后 Lab6 的 42 个功能点和 Lab7 的 68 个功能点全部通过，关键写回结果也和独立参考 CPU 一致。结合乘除法、分支及访存波形，可以看到新增指令已经接入原有五级流水线，并能够在阻塞、前递与访存控制配合下运行。
